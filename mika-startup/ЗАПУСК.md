# Startup guide

Run Python, uv, and developer tools through the Nix flake. The host
`llama-server` processes are the exception. Public templates are in
`startup/config/` next to this guide. Filled deployment files and the article
library remain local and must not be committed.

## 1. Verify the checkout

```sh
git clone -b develop git@github.com:BadRabbit00/Mika-Project.git
cd Mika-Project
nix flake check
nix develop --command python -m src.cli run --dry-run
```

The dry run uses synthetic articles, mocked models, and a temporary database.
It checks application wiring and makes no external deliveries. Real model
quality is checked separately after the model services are available.

## 2. Prepare local inputs

Use `mika-startup/startup/config/telegram.yaml` as the layout template. Fill the
copy at `config/telegram.yaml` with your owner ID, supergroup ID, and seven
distinct positive topic IDs. Preserve an existing filled configuration.
Leave `channel_id: 0` for group-only publication: Mika posts to the diary topic,
and the curator and operations bots use their assigned topics. A public channel
can be enabled later with its negative channel ID.

Create `.env` using the keys in `config/.env.example`:

```dotenv
MIKA_BOT_TOKEN=<mika token>
CURATOR_BOT_TOKEN=<curator token>
OPS_BOT_TOKEN=<operations token>
```

Keep the file readable only by its owner (`chmod 600 .env`). Both `run` and `bot`
read it automatically. `--env-file` selects another path; exported environment
variables take precedence. The YAML layout contains variable names, not tokens.

Supply your private `library/topics.yaml` and the first topic's six Markdown
articles. Article IDs, topic names, and origin keys must agree with the local
catalogue. Keep the complete `library/` directory outside Git. Startup reports
missing first-topic articles explicitly.

## 3. Start the model services

Use the generation model already selected in `config/settings.yaml` and the
matching local GGUF file under `~/.eva/models`. Start generation on port 8080
with the configured context capacity. Start embeddings on port 8081 using the
model identity configured for the stored graph vectors.

The locked embedding model is available through the flake:

```sh
nix build .#embedding-model --out-link result-embedding-model
```

Use the resulting file with the host embedding llama-server. The generation
service needs completion, chat-template, and `/tokenize` endpoints; the
embedding service needs embeddings. Check both services with `/health` before
starting the application. Authenticate the Claude Code CLI locally for curator
requests; model and effort settings come from `config/settings.yaml`.

## 4. Start the live application

```sh
nix develop --command python -m src.cli run \
  --layout config/telegram.yaml \
  --database data/mika.db \
  --log-file logs/mika.jsonl
```

World location and sleep scheduling are autonomous. Without a world-state file,
the first startup records neutral PAD and zero sleep debt. Restarts reuse the
stored state. Keep the JSONL log: it is the authoritative execution record.

## 5. Optional initial state and temporary overrides

`startup/config/world-state.json` illustrates an initial snapshot. Fill a local
copy at `config/world-state.json`, including an aware `initial_mood_at`, and add
`--world-state config/world-state.json` to the live command if needed.

`startup/config/world-override.json` illustrates temporary override fields.
Merge those fields into the same local world-state file before using it: the
file still needs `initial_mood`, `initial_mood_at`, and `initial_sleep_debt`.
Choose current aware timestamps and a future `valid_until`. Update a running
override file by atomic rename. When it expires, automatic providers resume.

## 6. Inspect operation

Use the operations bot in its private chat or the management topic:

```text
/health
/state
/graph stats
/defects
/outbox review
```

Use `/pause` and `/resume` to control learner scheduling. Supply new Markdown
articles in the library topic. Review uncertain outbox entries before taking
manual action; restarting the process does not resend uncertain deliveries.

For provider details, recovery rules, and the exact deployment contract, see
[LIVE_RUNTIME.md](../docs/LIVE_RUNTIME.md). CI and private-file checks are
documented in [CI.md](../docs/CI.md).
