# Startup guide

Nix with flakes enabled is required. Run the application, model servers, and
developer tools through this repository's flake. Run every command below from
the repository root. Public templates are in `startup/config/` next to this
guide. Filled deployment files and the article library remain local and must
not be committed.

## 1. Verify the checkout

```sh
git clone -b main git@github.com:BadRabbit00/Mika-Project.git
cd Mika-Project
nix flake check --no-update-lock-file
nix develop --command python -m src.cli run --dry-run
```

The dry run uses synthetic articles, mocked models, and a temporary database.
It checks application wiring and makes no external deliveries. Real model
quality is checked separately after the model services are available.

For an existing checkout, confirm that `flake.nix` and `flake.lock` are present.
An old checkout containing only the initial instructions must be updated first.
Use the flake's Python directly, as above. Do not activate `.venv` or prefix the
application command with `uv run`: it can select locally downloaded wheels
instead of the native dependencies built by uv2nix.

## 2. Prepare local inputs

Use `mika-startup/startup/config/telegram.yaml` as the layout template. Fill the
copy at `config/telegram.yaml` with your owner ID, supergroup ID, and seven
distinct positive topic IDs. Preserve an existing filled configuration.
Leave `channel_id: 0` for group-only publication: Mika posts to the diary topic,
and the curator and operations bots use their assigned topics. A public channel
can be enabled later with its negative channel ID.

Create `.env` using the keys in `config/.env.example`:

```dotenv
MIKA_BOT_TOKEN=<mika token>
CURATOR_BOT_TOKEN=<curator token>
OPS_BOT_TOKEN=<operations token>
```

Keep the file readable only by its owner (`chmod 600 .env`). Both `run` and `bot`
read it automatically. `--env-file` selects another path; exported environment
variables take precedence. The YAML layout contains variable names, not tokens.

Restore your private library, including **both** `library/topics.yaml` and the
first topic's six Markdown articles, from your local copy or backup. Git does
not supply these files. A directory containing only `.md` files is incomplete:
the catalogue defines the starting topic, topic relationships, article IDs,
and curator allocation rules. Article IDs, topic names, and origin keys must
agree with it. Keep the complete `library/` directory outside Git.

Validate it before starting any services:

```sh
nix develop --command python - <<'PY'
from src.catalogue import Catalogue

catalogue = Catalogue.load("library")
print(f"Library ready: {len(catalogue.topics)} topics, {len(catalogue.sources)} articles")
PY
```

If the library lives elsewhere, validate that directory instead and pass
`--library /absolute/path/to/library` to `run`. The directory must contain
`topics.yaml` alongside its articles. Missing first-topic articles are reported
by ID. The dry run uses synthetic data and does not validate your private library.

## 3. Start the model services

Keep each server running in its own terminal. The `models` devShell supplies
the llama.cpp version locked by `flake.lock`, with Vulkan support, and `curl`.
GPU use requires a working host Vulkan driver; check the detected devices:

```sh
nix develop .#models --command llama-server --list-devices
```

Start the selected Gemma 12B generation model on port 8080. Adjust the GGUF
path if your local model directory differs:

```sh
nix develop .#models --command llama-server \
  --model "$HOME/.eva/models/gemma-4-12b-it-uncensored-GGUF/gemma-4-12b-it-uncensored-Q4_K_M.gguf" \
  --host 127.0.0.1 \
  --port 8080 \
  --ctx-size 32768 \
  --parallel 1 \
  --reasoning off
```

`--parallel 1` gives the single request slot the full 32K context. There is no
`llama-server --grammar-dir` option. Mika reads `grammars/` and sends the
appropriate grammar with each generation request.

The locked embedding model is available through the flake:

```sh
nix build .#embedding-model --out-link result-embedding-model
nix develop .#models --command llama-server \
  --model "$PWD/result-embedding-model" \
  --host 127.0.0.1 \
  --port 8081 \
  --ctx-size 2048 \
  --parallel 1 \
  --batch-size 2048 \
  --ubatch-size 2048 \
  --embedding
```

Preserve the embedding model identity used by existing stored graph vectors;
an intentional model change requires `/graph reindex`. Both servers bind only
to loopback. In a third terminal, wait for both health checks to succeed:

```sh
nix develop .#models --command curl --fail --show-error http://127.0.0.1:8080/health
nix develop .#models --command curl --fail --show-error http://127.0.0.1:8081/health
```

The generation service supplies completion, chat-template, and `/tokenize`
endpoints; the embedding service supplies embeddings. Authenticate the Claude
Code CLI for curator requests through the application devShell:

```sh
nix develop --command claude auth login
```

Curator model and effort settings come from `config/settings.yaml`.

## 4. Start the live application

```sh
nix develop --command python -m src.cli run \
  --layout config/telegram.yaml \
  --database data/mika.db \
  --log-file logs/mika.jsonl
```

World location and sleep scheduling are autonomous. Without a world-state file,
the first startup records neutral PAD and zero sleep debt. Restarts reuse the
stored state. Keep the JSONL log: it is the authoritative execution record.

## 5. Optional initial state and temporary overrides

`startup/config/world-state.json` illustrates an initial snapshot. Fill a local
copy at `config/world-state.json`. Its example date is illustrative:
`initial_mood_at` must be timezone-aware and no later than the actual startup.
Use the time of the mood observation, or print the current UTC timestamp:

```sh
nix develop --command python - <<'PY'
from src.core.time_utils import now, to_utc_iso

print(to_utc_iso(now()))
PY
```

Set that value in your local file and add the file to the live command if needed:

```sh
nix develop --command python -m src.cli run \
  --layout config/telegram.yaml \
  --world-state config/world-state.json \
  --database data/mika.db \
  --log-file logs/mika.jsonl
```

`startup/config/world-override.json` illustrates temporary override fields.
Merge those fields into the same local world-state file before using it: the
file still needs `initial_mood`, `initial_mood_at`, and `initial_sleep_debt`.
Choose current aware timestamps and a future `valid_until`. Update a running
override file by atomic rename. When it expires, automatic providers resume.

## 6. Inspect operation

Use the operations bot in its private chat or the management topic:

```text
/health
/state
/graph stats
/defects
/outbox review
```

Use `/pause` and `/resume` to control learner scheduling. Supply new Markdown
articles in the library topic. Review uncertain outbox entries before taking
manual action; restarting the process does not resend uncertain deliveries.

## 7. Startup errors

- **`libstdc++.so.6` missing while importing NumPy:** the traceback usually points
  into `.venv`. Use `nix develop --command python ...` exactly as shown above;
  `uv run python ...` can reproduce the error even inside a devShell.
- **Missing `library/topics.yaml`:** restore the private catalogue as well as
  the articles, or select their existing directory with `--library`. Run the
  library validation in section 2. An empty catalogue is not a substitute.
- **Missing `--log-file`:** live operation requires a durable JSONL log. Include
  `--log-file logs/mika.jsonl` in the live command.
- **Snapshot later than startup / `Decay cannot run backwards`:** check the
  system clock and `initial_mood_at`. New future-dated snapshots are rejected
  before being saved. If an older release already saved one, editing or omitting
  the file does not reset `life_state['runtime.initial']`. Stop Mika and back up
  the database before correcting that stored timestamp. Preserve mood values
  and sleep records; existing mood history must not be silently rewritten.
- **Unknown `--grammar-dir` argument from llama-server:** remove that server
  flag. Only Mika's CLI accepts it, and its default is already `grammars/`.
- **Model service unavailable:** keep both server terminals running and check
  both health endpoints before starting Mika. Inspect the server output for
  model-loading, driver, or memory errors.

For provider details, recovery rules, and the exact deployment contract, see
[LIVE_RUNTIME.md](../docs/LIVE_RUNTIME.md). CI and private-file checks are
documented in [CI.md](../docs/CI.md).
